# INK Web Design Intelligence + Production System v0.1

## Direction

The long-term goal is not merely to clone websites.

The goal is to:

> 把網站拆成可理解、可重組、可學習的設計系統。

A conventional website-cloning workflow often aims for:

```text
URL / Screenshot
→ Generate a visually similar website
```

The INK WR direction should instead aim for:

```text
Website
→ Understand why the design works
→ Extract reusable design rules
→ Build reusable tokens / components / layout grammar
→ Decide what is worth preserving
→ Recompose with different content
→ Combine strengths from multiple references
→ Produce new original websites
```

## Four high-value capabilities

### 1. Not page cloning — extract the website grammar

Analyze and recover the underlying rules behind a website, including:

- layout rules;
- typography hierarchy;
- spacing rhythm;
- navigation logic;
- information density;
- image strategy;
- breakpoint and responsive behavior.

The target is not only visual resemblance. The target is a reusable model of how the presentation system works.

### 2. Build a design-preference model

Each selected website should contribute to an evolving understanding of the USER's design preferences.

Track dimensions such as:

```text
information density
whitespace
typography
navigation
image ratio / treatment
motion intensity
content architecture
```

The long-term goal is to reduce dependence on finding one perfect reference website. A growing preference model should help identify, compare and eventually generate design directions that fit the USER without requiring a direct clone.

### 3. Cross-site composition instead of single-site cloning

A future design system should be able to combine strengths from different references, for example:

```text
Site A → homepage rhythm
Site B → article structure
Site C → navigation model
Site D → project gallery
```

The result should become a new coherent system, not a stitched visual collage and not a direct copy of any one source.

### 4. Every reconstruction should increase future capability

Each reconstructed website should produce not only one finished site, but also reusable knowledge:

- component library;
- layout patterns;
- responsive patterns;
- typography systems;
- navigation patterns;
- verified implementation techniques.

Each completed case should improve the next case.

## Long-term framing

The long-term target should not be limited to:

**Website Cloning AI**

It should become:

**Web Design Intelligence + Production System**

Conceptually:

```text
Give the system one website
→ it understands that website

Give the system many selected websites
→ it increasingly understands the USER's design preferences

Give the system a new design requirement
→ it does not need to clone any single website
→ it can assemble an original, mature website from learned design grammar,
   reusable patterns and the USER's accumulated preferences
```

## Boundary

This direction concerns the Web portfolio / website-production lane.

It does not authorize changes to INK product/Core/Connector/workstation behavior.

It also does not require copying copyrighted website content. The subject of analysis and reproduction is the website presentation system:

```text
layout
architecture
navigation
components
responsive behavior
interaction patterns
social/external-link structures
```

Content, proprietary media, protected assets and private backend behavior remain outside the reproduction target unless separately licensed or owned.
