## Execution loop

USER instruction → inspect current source and rendered UI → bounded direct edit → meaningful checks → reversible GitHub commit → update current page and verify interaction/appearance → concise result → continue from USER feedback.

- Execute clear instructions without asking the USER to carry messages or reconfirm routine UI choices.
- Modify shell.template.html, then regenerate Web/Portable outputs; never hand-edit generated shells.
- Change the existing CSS/state authority; remove obsolete rules instead of adding competing overrides or presentation !important.
- Preserve existing Core capabilities, command mappings, Branding and document compatibility.
- Keep Core, FORMAT_VERSION, persistence and native mutation authorities intact. Escalate only an actual destructive migration, irreversible compatibility loss or replacement of a Core authority.
- Do not start GitHub Actions or expand QA infrastructure. Ordinary already-authorized commit-driven Pages deployment may continue.
- Verify through an available actual browser. Windows Chrome is not mandatory. Source/static checks do not prove rendered behavior.
- If one browser path is unavailable, finish independent authorized work and identify only the exact unverified items. Do not freeze the whole UI behind a numbered batch or an infrastructure search.
- Do not enable IMAGE generation without explicit USER image-generation/editing instructions.
- Record changes, validation, unresolved findings and rollback points in GitHub so another window can recover without this chat.
- Only USER declares visual/UI acceptance. Do not equate a cleanup, source check or partial browser pass with whole-product completion.

## Reports

Keep replies brief: what changed, what was actually verified, and any concrete remaining issue. Report verified facts; never invent screenshot measurements or claim checks that were not run.
